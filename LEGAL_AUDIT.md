# Legal audit draft

Дата аудита: 2026-06-24.
Проект: `krymvokrug.ru`, Next.js 16 / React 19 / Prisma / PostgreSQL / YooKassa / S3-compatible storage.

Этот файл является техническим аудитом репозитория и черновиком для последующей проверки юристом. Он не подтверждает полное соответствие законодательству.

## Найденная архитектура

- Frontend: Next.js App Router, React 19, Tailwind CSS, клиентские компоненты в `src/components`.
- Backend: Next.js route handlers в `src/app/api`, Prisma ORM, PostgreSQL.
- Авторизация: JWT/session cookies, личный кабинет владельца `/dashboard`, админка `/admin`.
- Публичные разделы: `/`, `/rent`, `/crimea/[location]`, `/crimea/[location]/[slug]`, `/excursions`, `/crimea/excursions/[location]/[slug]`, `/attractions`, `/transfers`, `/tours`, `/search`, `/about`, `/cooperation`, `/uslugi-i-tarify`.
- Юридические страницы до доработки: `/oferta`, `/legal/privacy`, `/legal/terms`, `/consent`.
- Формы: регистрация/логин/восстановление пароля, профиль, добавление/редактирование объектов, комнат, правил, цен, документов, медиа, отзывов, заявок, поддержки, экскурсий, трансферов.
- Платежи: `Payment` через `MANAGER` и `YOOKASSA`, маршруты `src/app/api/properties/[id]/payments/route.ts`, `src/app/api/yookassa/webhook/route.ts`, панели `src/components/payments/*`.
- Сторонние сервисы: YooKassa, Yandex Metrika, Yandex Maps/Geocoder, SMTP через `nodemailer`, Upstash Redis для rate limit при настройке, S3-compatible storage.

## Проблемы и исправления

| Не было production validation юридических обязательных полей | отсутствовало | Добавить `assertLegalConfigForProduction()` и вызывать в корневом layout при production |
| В оферте была формулировка "НДС не облагается, если это применимо" | `src/app/oferta/page.tsx` | Заменить на точный статус НПД из `legalConfig` |
| Не было страницы реквизитов | отсутствовало `/legal/requisites` | Создать страницу реквизитов с ФИО, ИНН, НПД, контактами, порядком претензий и чеками НПД |
| Не было полного набора юридических маршрутов | отсутствовали `/legal`, `/legal/cookies`, `/legal/refund`, `/legal/*-consent` | Добавить маршруты с версией, датой, постоянным URL, печатью и оглавлением |

| Оплата жилья технически не обнаружена как пользовательский checkout проживания | платежи связаны с размещением карточек | Зафиксировать запрет оплаты проживания в `legalConfig` и production validation |
| Нет журнала согласий | Prisma schema | Добавить модели `ConsentEvent`, `DocumentVersion`, поля evidence/version |
| Нет модели платформенного заказа и чека НПД поверх платежа | Prisma schema, `Payment` | Добавить `PlatformServiceOrder`, `NpdReceipt`, `RefundRequest`, интерфейс receipt provider |

| Запрос документов/видео лица был описан широко | `src/app/legal/terms/page.tsx`, `PropertyDocument` | Оставить как ручную верификацию с минимизацией данных и отдельным документом `VERIFICATION_SECURITY.md`; не публиковать паспортные данные |
| Footer не содержал весь требуемый набор ссылок | `src/components/layout/site-footer.tsx` | Добавить реквизиты, НПД, ИНН, privacy/consent/public consent/terms/oferta/refund/cookies/copyright и кнопку cookie settings |

## Персональные данные и места хранения

- `User`: телефон, имя, фамилия, email, avatar, хеш пароля, активность.
- `Property`: адрес, контакты владельца/контактного лица, email, телефоны, мессенджеры, сайт, описание, правила, публичные контакты.
- `Application`: имя, телефон, email, даты, количество гостей, сообщение.
- `PropertyDocument`: документы объекта, MIME, размер, URL/storageKey.
- `Media`, `SupportMessage`, `Review`, `ReviewReport`, `AttractionReport`, `ListingLead`, `ListingAnalyticsEvent`: пользовательский контент, события и технические идентификаторы.
- Storage: локально `public/uploads`, `storage/private-uploads`; при настройке S3 - внешний S3-compatible storage.
- Email: SMTP или log mode; SMS-сервис в коде не найден.

## Риски, которые нельзя закрыть кодом

- Нужен фактический почтовый адрес для претензий.
- Нужны подтвержденные сведения о размещении основной базы данных и файлового хранилища.
- Нужен номер уведомления/записи Роскомнадзора либо решение юриста о статусе уведомления.
- Нужны договоры с обработчиками: хостинг, S3, SMTP, YooKassa, Upstash, Yandex.
- Нужна юридическая проверка текстов оферты, согласий, возвратов и cookie policy.
- Нужна реальная интеграция с приложением "Мой налог" или утвержденный ручной процесс формирования чеков НПД.
- Нужна бизнес-процедура отзыва согласия на распространение публичных контактов и скрытия старых данных.

## Данные, которые должен предоставить владелец

- ФИО самозанятого, ИНН, телефон, email, контакт поддержки.
- Почтовый адрес для претензий.
- Страна и регион/ЦОД основной базы данных.
- Номер уведомления Роскомнадзора или юридическое решение о применимости.
- Перечень фактических обработчиков и стран размещения.
- Версии и даты вступления юридических документов после проверки юристом.
- Процедура и провайдер чеков НПД.
- Правила возврата по каждой платной услуге платформы.

## Реализовано после аудита

- Добавлена миграция `20260624170000_legal_compliance_foundation` для `ConsentEvent`, `DocumentVersion`, `PlatformServiceOrder`, `NpdReceipt`, `RefundRequest`, полей реестра и статуса `REQUIRES_REGISTRY_REVIEW`.
- Добавлен ручной провайдер чеков НПД: при отсутствии официальной интеграции статус остается `receipt_pending_manual_issue`.
- Добавлена форма `/refund-request` и API `/api/refund-requests` с серверной валидацией, CSRF через proxy и обязательным согласием на обработку данных.
- Добавлена админская очередь `/admin/registry-review`.
- Регистрация требует отдельное согласие на обработку персональных данных; маркетинговое согласие выключено по умолчанию и необязательно.
- Публичная CTA-кнопка карточки жилья переименована в "Отправить запрос владельцу"; модалка содержит предупреждение, что запрос не подтверждает бронирование.
- Footer дополнен реквизитами НПД, ИНН, юридическими ссылками и кнопкой настроек cookies.
