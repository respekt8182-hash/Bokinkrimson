# Personal data flow

## Категории субъектов

- Посетители публичного сайта.
- Зарегистрированные пользователи и владельцы объектов.
- Туристы, отправляющие заявки владельцам.
- Покупатели услуг платформы.
- Пользователи поддержки.
- Авторы отзывов и жалоб.
- Владельцы публичных контактов в карточках.

## Основные потоки

- Регистрация и вход: телефон, имя, фамилия, пароль в виде хеша, email при заполнении.
- Профиль: фото профиля, email, телефон, активность.
- Карточка объекта: адрес, контакты, мессенджеры, фото, описание, правила, цены, документы объекта.
- Заявка владельцу: даты, количество гостей, имя, телефон, email, комментарий. Сайт передает запрос, но не подтверждает бронирование.
- Оплата услуг платформы: сумма, услуга, тариф, владелец, провайдер, статус, версия оферты, данные для чека.
- Поддержка: текст сообщений, изображения, имя отправителя.
- Аналитика: события просмотров/действий и технические идентификаторы. Yandex Metrika должна запускаться только после opt-in.

## Хранилища

- PostgreSQL через Prisma.
- Local uploads: `public/uploads`, private uploads: `storage/private-uploads`.
- S3-compatible storage при наличии `S3_*`.
- YooKassa хранит платежные данные на своей стороне.
- SMTP-провайдер или log mode для email.

## Минимизация

- Не публиковать паспортные данные.
- Не раскрывать контакты без согласия на распространение.
- Не назначать согласие старым данным автоматически.
- Не загружать аналитику до согласия.
