# Public data migration

Не присваивать старым пользователям согласие автоматически.

Рекомендуемый порядок:

1. Создать резервную копию базы перед миграцией.
2. Добавить поля/таблицы согласий.
3. Для существующих публичных карточек пометить статус публичных контактов как `UNKNOWN`, если нет доказательства согласия.
4. В личном кабинете показать владельцу запрос на отдельное согласие на распространение публичных контактов.
5. До согласия показывать карточку без телефона, email и мессенджеров либо через форму заявки.
6. При отзыве согласия скрывать соответствующие данные и фиксировать событие в `ConsentEvent`.

Команда резервного копирования зависит от окружения. Для PostgreSQL обычно используется:

```bash
pg_dump "$DATABASE_URL" > backup-before-public-data-migration.sql
```

Добавленная миграция: `prisma/migrations/20260624170000_legal_compliance_foundation/migration.sql`.

Она не присваивает старым пользователям согласие автоматически и оставляет `contactsPublicationAllowed = false` по умолчанию.
